## 1. PROJECT EXECUTIVE SUMMARY & MISSION

- **Project Name**: ProjectNexus
- **Architecture Type**: MERN Stack (MongoDB, Express.js, React, Node.js)
- **Category**: Academic Project Lifecycle Governance, Jira-Style Progress Tracking & Versioned Project Continuity OS
- **Target Audience**: College Administrators, Department Heads (HODs), Faculty Project Guides, and Student Project Teams.
- **The Core Problem Solved**:
  Colleges run hundreds of student projects annually. Progress updates, code, and documentation are scattered across chats and local drives. When a student team abandons or discontinues a project at partial completion (e.g. 45%), the next team typically restarts from zero.
- **The Solution**:
  ProjectNexus centralizes project workflows with Jira-inspired task/milestone management and solves the continuity problem via a **Versioned Project Continuity Engine**. Handover packets preserve completed modules, pending deliverables, known technical debt/bugs, GitHub repository state, and faculty directives, enabling newly assigned teams to inherit projects seamlessly.

### The Flagship Demo Scenario
```
Admin creates Team Lead Invite ──> Team Lead A registers & creates "Smart Attendance System"
       │
       ▼
Team A adds 4 members, links GitHub repo, builds milestones, and reaches 45% completion
       │
       ▼
Team A discontinues ──> Admin marks Discontinued & generates Handover Packet
       │               (Completed modules, pending tasks, known bugs, GitHub state, faculty notes)
       ▼
Admin assigns Team Lead B ──> Team B enters "Continuation Workspace" (v2.0)
       │
       ▼
Team B inherits full history & resumes development immediately from 45% without starting from zero
```

## 2. USER ROLES & ACCESS CONTROL ARCHITECTURE

### The 3 Core Roles & Dashboards

| User Role | Assigned Dashboard | Core Permissions & Scope |
|---|---|---|
| **Admin** | **Admin Dashboard** | Generates Team Lead invitations, approves/rejects project proposals, monitors institution-wide progress, views stagnant/overdue alerts, executes project discontinuation & assigns continuation teams, archives projects. |
| **Team Lead** | **Team Dashboard & Workspace** | Registers team via invitation token, invites team members, submits project proposal, creates milestones & Jira-style tasks, submits weekly updates, links GitHub repo, initiates handover if discontinued. |
| **Team Member** | **Team Dashboard & Workspace** | Views assigned project, updates own assigned task status (`To Do` $\rightarrow$ `Done`), logs progress comments. Cannot alter team ownership or project settings. |

### Strict Access & Registration Rules
1. **No Self-Assigned Admins**: Registration routes forbid selecting the "Admin" role. Admin accounts are seeded or provisioned directly.
2. **Invitation-Gated Registration**:
   - Admin generates a secure invitation token with an expiration date for a Team Lead.
   - Team Lead registers via that invitation token $\rightarrow$ creates the Team profile.
   - Team Members register via a unique team invite link/code generated by the Team Lead.
3. **Backend-Enforced Authorization**:
   - Express middleware verifies JWT tokens and checks user roles/team ownership on every endpoint. Hiding UI elements on the frontend is treated purely as UX, never security.
4. **Single Active Team Policy**: A student member can only belong to one active team at any given time.

## 3. PROJECT LIFECYCLE & VERSIONING WORKFLOW

```
[Draft] 
   │
   ▼
[Pending Approval]  ──(Admin Rejection / Changes Requested)──> [Draft / Revisions]
   │
   ▼ (Admin Approval)
[Active (v1.0)] ────(Project Completed)────> [Completed] ──> [Archived]
   │
   ▼ (Team Stops / Incomplete)
[Discontinued]
   │ (Handover Packet Generated)
   ▼
[Handed Over]
   │ (New Team Assigned -> v2.0)
   ▼
[Active (v2.0 Continuation Workspace)]
```

## 5. COMPLETE UI & DASHBOARD ARCHITECTURE

### A. Institutional Admin Monitoring Dashboard
- **Top 6 KPI Summary Cards**:
  1. *Total Projects*: All registered projects in institution.
  2. *Active Projects*: Currently in-flight projects.
  3. *Pending Approval*: New proposals awaiting faculty/admin approval.
  4. *Stagnant Projects*: Projects with $\ge 7$ days without a weekly update (with real-time warning pulse).
  5. *Overdue Milestones*: Projects with milestones exceeding due dates.
  6. *Completed Projects*: Finished projects ready for archival.
- **Intervention Alert Banners**:
  - Highlights specific stagnant projects (e.g., *AI Health Diagnostic Assistant*, 11 days inactive) with **Inspect Workspace** and **Send Reminder Nudge** actions.
- **Project Master Registry**:
  - Real-time search across titles, leads, tech stacks, and departments.
  - Filter tabs (`All`, `Active`, `Pending`, `Stagnant`, `Completed`).
  - Progress bars, last update indicators, and direct GitHub links.
  - One-click approval/rejection and Discontinue/Handover action triggers.

### B. Team Dashboard & 9-Tab Workspace
- **Header**: Project title, version badge (`v2.0 Continuation`), dynamic progress ring, team roster, and days-since-last-update badge.
- **The 9 Integrated Workspace Tabs**:
  1. **Overview**: Problem statement, scope abstract, tech stack pills, team roster.
  2. **Team Members**: Roster, roll numbers, assigned tasks count, "+ Invite Member" code generator.
  3. **Task Board (Jira-Style Kanban)**:
     - 4 Columns: `To Do` | `In Progress` | `Under Review` | `Done`.
     - Priority tags (`High`, `Medium`, `Low`), assignee avatars, due dates.
     - Live sync progress recalculation:
       $$\text{Project Progress} = \left( \frac{\sum \text{Done Tasks}}{\sum \text{Total Tasks}} \right) \times 100$$
     - "+ Create Task" modal.
  4. **Milestones**: Phased milestone progress bars, due dates, and faculty feedback notes.
  5. **Weekly Updates**: Submission form (Completed work, blockers, next week's plan) and timeline feed.
  6. **GitHub Repository**: Read-only GitHub stats widget (commit count, contributors, stars, branch, latest commit).
  7. **Documents / Links**: Resource vault for SRS documents, architecture specs, and dataset drives.
  8. **Activity Timeline**: Chronological audit trail of team actions and task movements.
  9. **Handover History (Flagship)**: Interactive packet view comparing `v1.0 (Team Alpha)` and `v2.0 (Team Beta)` — showcasing inherited completed deliverables, pending targets, known bugs, and faculty guidance.
